# 2. 이 버전에서 반드시 느껴져야 하는 것

v1.0에서 검증할 재미는 세 가지뿐이다.

### A. 정책이 정당의 색을 만든다

플레이어가 반복해서 선택한 **공약**이 누적되어 주거 실용주의, 복지 확대, 시장친화, 지역분권, 과학기술, 정치개혁 등의 정체성이 자연스럽게 만들어져야 한다.

### B. 좋은 정책이 곧바로 표가 되지 않는다

정책 적합도가 높아도 낮은 인지도, 약한 지역조직, 후보 부족, 전략투표, 사표 우려 때문에 실제 득표로 전환되지 않을 수 있어야 한다.

### C. 선거 결과가 다음 게임을 바꾼다

의석 수는 숫자 차이가 아니라 다음 시즌의 정치적 가능성을 바꾸는 결과여야 한다. **0석은 득표율에 따라 ‘원외 존속’과 ‘정당 등록취소’로 갈린다 (§27).**

v1.0은 총선 직후 종료하지만 Season Review에 “다음 시즌 해금 요소”를 보여준다.

## State

- IndexedDB

## 시뮬레이션
- 순수 TypeScript engine (React·DOM 비의존)

## 배포
- GitHub Actions, GitHub Pages
- Vite `base`를 저장소 경로에 맞춰 설정한다.
- 라우팅은 `HashRouter` 또는 `404.html` 폴백 중 하나로 SPA 새로고침 문제를 막는다.
- GitHub Free 플랜은 Pages에 **공개 저장소**가 필요하다.

## 원칙

# 7. 선거제도 Ruleset

## 7.1 원칙

- 2028년 선거제도는 **미확정**이다 (기준일 2026-10-18). 이 게임은 실제 제도를 예측한다고 주장하지 않는다.
- 2028-04-12 선거일은 `SCHEDULED`(예정) 상태이며 확정 공고가 아니다. 아래 7.2의 정당 입장·발의안은 보도 기반 맥락이며 `REAL_FACT` 레코드로 적재하지 않는다(구현: `docs/DATA_VERIFICATION.md`).
- 선거 규칙은 코드에 하드코딩하지 않고 **Ruleset 데이터 파일**로 둔다. 254, 46, 3% 같은 숫자는 전부 파라미터다.
- 세이브는 `rulesetId`를 저장한다. 화면에는 항상 다음을 표시한다.

> **이 세이브의 선거제도: {label}**
> 실제 2028년 선거제도는 아직 확정되지 않았습니다. 이 규칙은 게임용 가정입니다.

## 7.2 Reality Pack에 기록할 현재 상태 (기준일 2026-10-18)

- 현행 법제: 지역구 254 + 비례 46, **준연동형**(2020·2024 총선 적용)
- 헌법재판소가 2026-01-29 비례 **3% 봉쇄조항을 위헌 결정**. 대체 기준은 미입법
- 국민의힘이 병립형 복귀를 당론으로 추진 중(2026-09). 더불어민주당은 입장 미정
- 2028 선거구 획정은 미확정이므로 254는 임시값
- 법제·헌재 결정·획정 상태는 `REAL_FACT`(출처·검증일 필수)이고, 미해결 여부는 `status: "UNRESOLVED"`로 표기한다. 정당의 당론·입장은 게임 맥락 설명일 뿐 `REAL_FACT`로 적재하지 않는다.

## 7.3 프리셋

| ID | 설명 | v1.0 구현 |
|---|---|---|
| `parallel_46_open` **(기본값)** | 병립형. 지역구 254 + 비례 46을 독립 배분. 법정 문턱 없음 | **필수** |
| `parallel_46_threshold_3` | 위와 같되 구 3% 문턱을 복원한 입법 시나리오 | **필수** (파라미터 차이뿐) |
| `semi_compensatory_30` | 준연동형. 연동 배분 상한 30석, 나머지 병립. 위성정당 모드 포함 | **선택** (스키마·엔진 훅은 필수, UI 노출은 구현 완료 시) |

### 기본값을 병립형으로 잡은 이유
1. 준연동형은 양당의 위성정당 대응이 핵심인데, v1.0에는 AI 정당의 위성정당 행동 모델이 없다. 이를 빼고 구현하면 소수정당이 비현실적으로 유리해진다.
2. 개편 논의의 중심에 병립형 복귀가 있고, 문턱 폐지로 “비례 1석 정당”이 가능해진 현재 상태를 반영하기 쉽다.
3. 배분 결과를 손계산으로 검증할 수 있어 결정론 테스트에 적합하다.

법정 문턱이 없어도 46석 배분에서는 사실상의 문턱이 생긴다(대략 1/46 ≈ 2.2% 전후, 잔여 배분 결과에 따라 달라짐). 이 점은 Season Review와 Data Hub에 설명으로 노출한다.

## 7.4 Ruleset 스키마 (예시)

```yaml
rulesetId: parallel_46_open
label: "병립형 46 · 법정 문턱 없음 (게임용 가정)"
electionDate: 2028-04-12
districtSeats: 254              # 선거구 획정 전 임시값
listSeats: 46
listMethod: parallel            # parallel | semi_compensatory
listAllocation: hare_largest_remainder
legalThreshold: null            # 예: { voteShare: 0.03, orDistrictSeats: 5 }
semiCompensatory: null          # { coupling: 0.5, cap: 30, satelliteMode: ... }
districtRule: plurality_single_member
officialCampaignDays: 13
dualCandidacy: false            # UNVERIFIED: 지역구·비례 중복 등록 금지로 알고 있음
listGenderRule: odd_positions_female   # UNVERIFIED: 홀수 순번 여성 추천
listSizeUi: { min: 10, max: 15 }
partyRevocation:                # UNVERIFIED: 의석 0 + 득표율 기준 미만이면 등록취소
  seatsEq: 0
  listVoteShareBelow: 0.02
deposit:                        # UNVERIFIED: 금액·반환 기준
  perDistrictCandidate: 15000000
  refundFullAbove: 0.15
  refundHalfAbove: 0.10
  partyList: 50000000
campaignCostReimbursement:      # UNVERIFIED
  fullAbove: 0.15
  halfAbove: 0.10
```

- `UNVERIFIED` 표시 항목은 **임시 가정값**이다. Reality Pack에는 `status: "UNVERIFIED_ASSUMPTION"`으로 기록한다.
- 개발 빌드에서는 경고, **릴리스 빌드에서는 CI 실패**로 처리해 공개 전에 선관위·법제처 자료로 검증하게 한다.

## 7.5 배분 요구사항

- 지역구: 단순 다수대표.
- `parallel` 비례: 문턱을 통과한 정당들의 정당득표로 Hare 몫 + 최대잔여 방식 배분. 득표 0, 문턱 미달 정당은 제외.
- `semi_compensatory`: 정당별 목표의석 = (총 의석 × 득표율 − 지역구 당선) × 연동률(0.5), 연동 배분 상한 30, 나머지 병립. 위성정당 모드 값은 `none | major_parties_neutralize`. 손계산 예제 테스트를 반드시 둔다.
- 모든 프리셋에 대해 “의석 합 = 254 + 46”, “정당별 비례 의석 ≥ 0”, “득표 증가가 의석을 감소시키지 않음(단조성)” 속성 테스트를 둔다.

## 핵심가치는 즉시 능력치 보너스를 주지 않는다

법적 창당 절차(창당준비위원회, 시도당 등록 등)는 생략하는 추상화이며 창당 화면에 그 사실을 한 줄로 밝힌다.

# 9. 초기 상태, 자원, 재정

## 초기 정당 상태
```text
국회의원       0
지방의원       0
당원        8,000~15,000
전국 인지도   낮음
조직력         매우 낮음
재정           제한적
```
첫 18개월의 목표는 “전국적 거대정당”이 아니라 “생존 가능한 원내정당”이다.

## 자원 3종
| 자원 | 의미 | 갱신 |
|---|---|---|
| **Money** | 게임 내 단위(백만 원 환산)의 가용 자금 | 매주 정산 |
| **Staff Capacity** | 실무진이 이번 달 처리할 수 있는 업무량 (정책 연구, 영입 접촉, 조사, 조직 활동에 소모) | 매월 충전, 상근자·사무소에 따라 증가 |
| **Agenda Slots** | 이번 달 공개 발표 가능한 정책·메시지 횟수 | 매월 충전 |

- 원본의 “Political Attention”은 유권자 쪽 `salience`(대중 관심)와 이름이 겹쳐 **Agenda Slots**로 개명한다.
- 화폐를 더 늘리지 않는다.

## Money 수입·지출
- 수입: 당비(당원 수 × 납부율 × 평균 당비). 원외 정당은 **국고보조금이 없거나 제한적**이라고 가정한다 (`UNVERIFIED`, 지급 요건은 Reality Pack에 기록).
- 지출: 상근 인건비, 사무소 임대, 정책 연구, 영입·조직 투자, 여론조사 의뢰, 선거 비용.
- 선거 비용: 지역구 후보별 **기탁금**과 비례 정당 기탁금 (§7.4). 득표율이 낮으면 기탁금을 잃는다. 후보를 많이 내면 비용이 커지는 트레이드오프가 의도다.
- 선거비용 보전도 득표율 기준에 따라 환급된다 (§7.4).
- 초기 Money, 단가는 밸런스 파라미터로 둔다.

# 10. 공약과 집행: 정책의 두 계층

플레이어 정당은 원외 정당이므로 **자기 정책을 집행할 수 없다.** 따라서 정책을 두 계층으로 나눈다.

| 계층 | 주체 | 하는 일 |
|---|---|---|
| **공약(Platform)** | 플레이어 정당, 모든 AI 정당 | 인식, 정체성, 이슈 소유, 전문성, 코호트 적합도에 작용한다. 사회 지표를 직접 바꾸지 않는다. |
| **집행(Government Policy)** | 집권당(Reality Pack의 `governingPartyId`) | 사회 지표(이슈 severity/trend)에 실제로 영향을 준다. 집행에는 시차가 있다. |

- 집권당 AI는 자신의 공약, 경제 상태, 유권자 수요, 이슈 압력을 보고 `enactedPolicy`를 분기별로 갱신한다.
- 플레이어는 직접 집행하지 못하지만, 이슈 salience를 키워 집권당의 정책 선택에 간접 압력을 줄 수 있다 (선택 구현, 약한 효과).
- 정책 화면의 “예상효과”는 **“이 공약이 집행될 경우의 전망”**이라고 표기한다.
- 정치개혁 영역의 선거제도 레버는 **공약일 뿐 Ruleset을 바꾸지 않는다.** 국회 시뮬레이션이 없는 v1.0에서는 선거제도 변경이 일어나지 않는다.

# 11. v1.0 정책 영역과 레버

전체 12개 중 6개만 깊게 구현한다. 나머지는 배경 이슈로만 존재한다.

## 레버 의미: 0~4

- 각 레버는 **현행 대비 방향**을 나타낸다. **2 = 현행 유지**, 0 = 대폭 축소·완화, 4 = 대폭 확대·강화. 각 레버에는 “4가 무엇을 뜻하는지”를 나타내는 축 이름을 둔다.
- 초기 공약값은 정당 prior에서 오며, 플레이어 정당은 모두 2(현행)에서 시작하지 않고 **아직 공표하지 않은 상태**(`unpublished`)다. 공표해야 인식에 반영된다.

## 영역별 레버

| 영역 | 레버 (4의 방향) |
|---|---|
| **주택** | 민간공급 확대 / 공공주택 확대 / 재건축·재개발 촉진 / 청년·생애최초 금융지원 확대 / 보유세 강화 / 임대지원 확대 |
| **저출생·가족** | 양육 현금지원 확대 / 보육·돌봄 인프라 확대 / 육아휴직·일가정 양립 강화 / 신혼·출산 주거연계 확대 / 교육비 경감 확대 |
| **연금** | 보험료율 인상 / 소득대체율 인상 / 기초연금 확대 / 자동조정장치 도입 강화 / 퇴직·개인연금 활성화 |
| **의료** | 의료인력 정원 확대 / 필수·지역의료 지원 확대 / 건강보험 보장성 확대 / 공공병원 확대 / 수가 보상 확대 |
| **산업·AI** | 연구개발 투자 확대 / AI·반도체 인프라(전력·데이터센터) 확대 / 규제 완화 / 스타트업·벤처 금융 확대 / 재생에너지 중심 에너지믹스 / 노동시장 전환지원 확대 |
| **정치개혁** | 선거제도 비례성 강화 / 정당·정치자금 개혁 / 국회 운영·특권 개혁 / 권력구조 분권(개헌) / 지방자치 권한·재정 확대 |

(레버 이름은 가안이다. 세부 문구는 구현 단계에서 조정해도 되지만 **개수(5~6개)와 축 구조는 유지**한다.)

## 공약 변경 규칙
- 레버 값을 바꾸는 것은 자유(초안)지만, **공표**하려면 Agenda Slot 1칸과 Staff Capacity가 든다.
- 이미 공표한 레버를 6개월 이내에 반대 방향으로 바꾸면 **일관성(consistency)** 하락 → 신뢰 하락.
- 레버를 현행(2)에서 많이 벗어날수록 재정 부담 전망이 커지고, **재원 현실성** 인식이 낮아질 수 있다. 전부 4로 올리는 우월 전략이 생기지 않도록 한다.
- 공약 신뢰도 = 전문성(Expertise) × 재원 현실성 × 일관성의 함수.

# 14. 핵심가치 ↔ 정책·신호 매핑

핵심가치 10개는 6개 정책 영역만으로 측정할 수 없다. 모든 가치는 **레버 태그** 또는 **비(非)레버 신호** 중 하나 이상으로 측정되어야 한다. 레버에는 `valueTags: { 가치: 가중치 }`를 데이터로 둔다.

| 핵심가치 | 측정 방식 |
|---|---|
| 정치개혁 | 정치개혁 영역 레버(비례성, 정치자금, 국회 운영) + 비례명부의 정치 신인 비율 |
| 주거개혁 | 주택 영역에서 현행(2)을 벗어난 레버 수·폭 + 주택 전문성 |
| 세대교체 | 후보·비례명부의 평균 연령과 청년 비율 + 연금 레버(자동조정, 보험료율)의 세대 형평 방향 |
| 시장경쟁 | 민간공급, 규제 완화, 스타트업 금융, 퇴직·개인연금 활성화 등 `market` 태그 레버 |
| 사회안전망 | 기초연금, 건강보험 보장성, 임대지원, 돌봄 인프라 등 `safety_net` 태그 레버 |
| 지역분권 | 지방자치 레버 + 필수·지역의료 레버 + 지역조직 투자의 권역 분산도 + 비례명부의 지역 대표 |
| 과학기술 | 연구개발, AI·반도체 인프라 레버 + 이공계 비례후보 비율 |
| 노동개혁 | 노동시장 전환지원, 육아휴직·일가정 레버 + 노동 대표 비례후보 |
| 기후전환 | 에너지믹스 레버 + 전력·에너지 관련 이슈 대응 |
| 정부효율 | 국회 운영·정당 개혁 레버 + 공약 전체의 재원 현실성 |

## Brand consistency
선언한 핵심가치 3개와 실제 공약·후보 구성·행동의 일치도다. 평가 요소는 다음과 같다.
- 공약의 `valueTags` 합계
- 비례명부·지역구 후보 구성
- 영입 인물의 성향

핵심가치와 어긋나는 행동이 누적되면 정체성 신뢰가 떨어진다. 단순 점수 보너스는 주지 않는다.

# 15. 사회 이슈 엔진

6개 이슈에는 `severity`, `salience`, `trend`가 존재한다.

```text
주택

Severity  71
Salience  83
Trend     악화
```

## 이슈 변화
- 월 1회 큰 업데이트 (매주 계산하지 않는다)
- 영향 요인: 경제 상태, 기존 문제, **집권당의 집행 정책(`enactedPolicy`)**, 외생 충격
- 플레이어 공약은 이슈를 직접 바꾸지 않고 salience와 인식에 작용한다.

## 이슈 이벤트
상태에서 동적으로 생성한다. 예: 수도권 월세 부담 악화, 지역 필수의료 공백 확대, AI 데이터센터 전력수요 논쟁. 현실 뉴스를 재현하지 않는다.

# 16. 유권자 코호트

MVP에서는 96개다. 구성: 8 정치권역 × 4 연령대 × 3 생활조건 프로필.

## 8 권역 (17개 시도 매핑 표를 Reality Pack에 둔다)
서울 / 경기·인천 / 충청(대전·세종·충북·충남) / TK / PK / 호남(광주·전북·전남) / 강원 / 제주

현실 DB는 17개 시도를 유지하되 MVP voter simulation은 8권역으로 묶는다.

## 4 연령대
18~29 / 30~44 / 45~59 / 60+ (경계는 `ageBands` 설정값. 가중치는 Reality Pack의 연령별 유권자 수에서 온다.)

## 3 생활조건 프로필
- **A. Housing Pressure**: 무주택·임차 비중 높음
- **B. Family & Work**: 가족·교육·고용 이슈 비중 높음
- **C. Asset & Retirement**: 자가·노후·연금·의료 비중 높음

## 가중치 규칙
- 프로필은 연령×권역의 **조건부 분포**다. 단순 직교곱이 아니다 (예: 20대의 Asset & Retirement는 매우 작은 가중치).
- 가중치가 0에 가까운 셀도 코호트로 유지한다 (총 96개).
- 초기 선호는 인구 구조와 **별도로** 보정한다. “서울 청년은 X당” 같은 하드코딩 금지.

## 코호트 속성
weight, issue salience, party attachment(직전 선거 투표 기반), policy preference, political attention, turnout tendency, tactical-voting tendency, 정권평가(국정 평가 태도).

# 17. 지역구 모델

## 두 계층
- **254개 전체: 경량 레코드(Light).** 모든 지역구에 `regionId`, 코호트 구성비 벡터(12셀: 연령4 × 프로필3), 2024 총선 기준 정당별 득표 baseline, 현역·후보 정보, 선거 결과 계산에 필요한 최소값을 둔다. 플레이어가 개입하지 않는 지역구는 권역 단위 배경 모델과 이 레코드로 결과를 계산한다.
- **30개: 상세(Active).** 플레이어가 목표로 선택할 수 있다. Light 레코드에 더해 지역 이슈 적합도, 조직, 후보 정보, 전략투표 위험 등을 둔다.

Active 30개 구성(가안, 권역별): 서울 6 / 경기·인천 8 / 충청 4 / PK 4 / TK 2 / 호남 2 / 강원 2 / 제주 2. 선정은 지역 다양성과 접전도를 기준으로 하고, 선정 기준은 Reality Pack에 기록한다.

(원본 §27의 “254개 선거 직전 활성화”는 삭제했다. 상세 활성화 대상은 30개뿐이다.)

## 코호트 → 지역구 연결
96개 코호트는 권역 단위이므로 지역구 단위 득표는 **권역 코호트 선호 × 지역구 구성비 벡터 + 지역 baseline 잔차**로 계산한다. 구성비 벡터 없이 권역 값을 그대로 쓰지 않는다.

## Target District
- 실제 지역구 명칭을 사용할 수 있다. 단 실제 선거 예측이 아니라 Save 내부 모델임을 명시한다.
- 플레이어는 10~20곳에 집중한다.
- 지역구 평가 항목: Party Fit / Organization / Candidate / Strategic Voting Risk / Local Issue Fit

# 18. 투표 판단 모델

수식은 **기호 정의를 먼저 두고 한 단계씩** 쌓는다. 아래는 구조 지침이며 계수는 설정값이다.

## 18.1 기호 정의
- c: 코호트, p: 정당, d: 정책 영역
- s_cd ∈ [0,1]: 코호트 c가 영역 d를 중요하게 보는 정도(salience)
- fit_cpd ∈ [0,1]: 코호트 c의 선호와 정당 p의 **공표된 공약**이 영역 d에서 가까운 정도
- A_cp ∈ [0,1]: 코호트 c가 정당 p를 인지하는 비율
- I_cp: 정체성 거리(이념·정체성 축에서 c와 p의 거리가 가까울수록 큼)
- T_cp: 정당 신뢰(Issue Ownership, 공약 신뢰도, 일관성)
- L_cp: 기존정당충성(직전 선거 투표 정당이면 큼)
- G_cp: 정권평가 항 (§18.3)
- V_cp: 생존가능성(viability) 인식. 사표 우려의 반대 (§19)
- ε_cp: 오차

## 18.2 단계별 구성
1. **정책 적합도**: F_cp = Σ_d s_cd · fit_cpd / Σ_d s_cd
2. **효용**: U_cp = β1·F_cp + β2·I_cp + β3·T_cp + β4·L_cp + β5·G_cp + β6·V_cp + ε_cp
3. **인지 게이트**: 코호트는 정당 p를 A_cp 확률로만 고려 집합에 넣는다. 인지하지 못한 정당은 선택 불가.
4. **선택**: 고려 집합에서 U_cp에 대한 다항 로짓(softmax)으로 선택 확률을 구한다.
5. **투표율 반영**: 코호트 투표 성향을 곱해 득표로 환산한다.

## 18.3 정권평가 (G_cp)
총선은 정권 중간평가 성격이 크다. 집권당 p에는 국정 평가가 좋으면 +, 나쁘면 −를 주고, 비집권 정당에는 반대 방향(심판 성향)을 주되 코호트별 정권평가 태도로 가중한다. Reality Pack은 `presidentApproval` 계열 지표를 **기준일·출처와 함께** 가진다.

## 18.4 두 개의 투표
- **정당투표(비례)**: 후보·지역조직 항 없음. V는 전국 단위 생존가능성.
- **지역구투표**: 위 U에 **후보 항(C_cp)**, **지역조직 항(O_cp)**, **지역 이슈 적합(LI_cp)**을 더하고 V는 지역구 단위로 계산한다.

두 투표는 분리해서 계산한다 (스플릿 투표 가능).

## 18.5 Potential Support와 Current Support
- **Potential Support**: 인지도와 생존가능성 장벽을 **모든 정당에서** 제거한 가상 상태에서 정당 p의 득표 확률. 모든 정당의 A_cp=1, 모든 정당의 V를 동일한 중립값 `V_neutral`로 둔다. `V_neutral` = 현재 지지 상위 두 정당 V의 평균(반올림, 동률은 정당 id 순). 신뢰·기존 충성·정체성 거리·정부평가는 유지한다. 즉 정책·정체성·신뢰만으로 얼마나 가까운가. 강제 보정(clamp)은 없으며 대정당은 Potential이 Current보다 낮을 수 있다. (사용자 확정, B2에서 구현)
- **Current Support**: 실제 A, V, L을 모두 반영한 현재 선택 확률.
- 둘의 차이는 UI에서 반드시 보여야 한다. **Barrier 분해**는 장벽을 하나씩 제거했을 때 늘어나는 폭으로 계산한다 (인지도 / 전략투표 / 기존충성 / 지역구에서는 조직).

# 19. 전략투표

반드시 구현한다. 지역구에서 플레이어 후보가 비(非)유력이면 선호자가 다른 정당에 투표한다.

- 인식 생존가능성 V는 **지역구 여론 지지율과 1·2위와의 격차**에서 계산한다. S자(비선형) 함수여야 하며 변곡 구간은 대략 15~30% 사이다. 값은 설정값이다.
- 예: 3등 후보가 지지율 10%일 때와 26%일 때 사표 인식이 확연히 달라져야 한다.
- 지지율이 오르면 누수가 **비선형으로 감소**한다. “모멘텀 보너스” 같은 마법 항은 쓰지 않는다.
- 비례투표의 V는 전국 지지율과 문턱 여부(Ruleset)에서 나온다.

# 20. 정치인·후보

## 20.1 이중 구조
| 종류 | 대상 | 속성 |
|---|---|---|
| **Full 객체** | 실존 핵심 정치인(≤ 20) + 플레이어가 영입·육성하는 가상 정치인(≤ 60) | 8개 속성 + 영역별 전문성 + 약속·관계 이력 |
| **Light 레코드** | AI 정당의 지역구 후보, 배경 후보 | 3개 속성(Recognition, LocalBase, Strength) |

## 20.2 인원
- 실존 핵심 정치인 약 20명: 양당 지도부, 군소정당 대표, 전국적 정치 행위자로 제한
- 영입 가능한 가상 정치인: 시작 시 약 30명 + 매월 1~3명 추가 생성
- 필요 후보 수: 지역구 최대 30명 + 비례 10~15명 = **최대 45명**. `dualCandidacy: false`이면 서로 다른 사람이어야 한다.
- 따라서 **2027-12-06까지 영입·발굴 가능한 가상 인물 누적 공급 ≥ 50명**을 생성기가 보장한다 (지역조직 투자가 후보 발굴 확률을 올린다).

## 20.3 생성 방식
- 가상 정치인은 **시드로 생성**한다. 배경(지방의원, 정책연구원, 변호사, 의사, 간호사, 엔지니어, 교사, 기업가, 노동운동가, 시민단체 활동가, 전직 보좌진 등)과 권역·전문 영역 분포를 시드로 뽑는다.
- 원본의 서하진·박민재·윤지호는 **아키타입 예시**다. 이름은 시드마다 달라질 수 있다.
- 이름 생성 시 Reality Pack의 실존 정치인 이름과 **충돌하지 않는지 검사**한다 (validator 포함).
- 플레이어의 핵심 감정 이입은 가상 정치인 육성에 둔다. 실존 정치인을 “수집”하는 게임으로 만들지 않는다.

## 20.4 속성 (MVP 정확히 8개)
```text
Recognition   LocalBase   Campaigning   Organization
Media         Negotiation PolicyExpertise(영역별)   BroadAppeal
```
- **Negotiation**: v1.0에서는 영입 협상 성공률과 공천 갈등 조정에만 쓴다. (국회·단일화 협상은 v1.1 이후)
- 지성, 도덕성, 정직, 애국심, 부패 성향, 정신 안정성 같은 속성은 두지 않는다.
- 실존 정치인의 능력치는 모두 **GAME MODEL 추정치**임을 표기한다.

# 29. Save와 결정론

## 필수 기능
자동저장, 수동저장, JSON Export, JSON Import

## Save 필드
```text
schemaVersion
seed, rngState(스트림별)
realityPackId, realityPackAsOf
rulesetId (+ 사용된 Ruleset 스냅샷)
date
party (공약 초안/공표, 핵심가치, Expertise, Ownership)
resources (Money, Staff Capacity, Agenda Slots), finance
politicians (Full), lightCandidates
promises
aiParties (공약, 집행 정책 enactedPolicy, 상태)
issues, voters(cohorts), districts(Light/Active)
polls, inbox, events(event log)
election state, campaign settings
commandLog (선택: 재현·디버깅용)
```

## 결정론
같은 Save + 같은 선택 + 같은 seed면 같은 결과가 나와야 한다.
- RNG는 **서브시스템별 독립 스트림**(예: polls, ai, recruitment, election)으로 분리하고 `(seed, 서브시스템, 날짜)`로 파생한다. 기능을 추가해도 다른 곳의 난수열이 흔들리지 않는다.
- `Math.exp`, `Math.log`, `Math.pow`, 삼각함수 등은 JS 엔진마다 결과가 미세하게 다를 수 있다. 결과가 달라질 수 있는 연산은 **직접 구현하거나 정해진 표/정밀도로 대체**하고, 반올림 규칙을 고정한다.
- 반복 순서는 항상 정렬된 ID 기준으로 고정한다.
- 검증: 저장 후 불러온 상태의 **해시**가 원본과 같아야 하고, `commandLog` 재생 해시와도 같아야 한다.

seeded RNG / 정책 효과 / 코호트 효용 / 여론조사 오차 / 전략투표 / 지역구 득표 / 의석 배분(프리셋별) / 저장·불러오기 결정론 / Ruleset 속성(§7.5)

## 시뮬레이션
- **AI-only 2026→2028**: 플레이어 정당을 **기본 AI 봇(균형형 공약)**이 대신하는 세계를 여러 시드로 실행. CI(Continuous Integration, 지속적 통합)에서는 소수 시드(예: 20)만, **전체 규모(500회)는 야간·수동 실행**.
- 확인 지표: NaN 없음 / 의석 합 정합 / 제1당 분포가 한쪽으로 100% 쏠리지 않음 / 과반 확률이 합리적 범위 / 제3당 의석 분포가 항상 0도 항상 고의석도 아님

## 봇 플레이어 (밸런스 측정용)
| 봇 | 전략 |
|---|---|
| idle | 아무것도 하지 않음 |
| balanced | 6개 영역 고르게, 조직 균등 투자 |
| specialist | 주택 집중 + 소수 권역 조직 집중 |
| regional | 특정 권역 조직과 지역구 집중 |

- 같은 전략·다른 시드의 결과 분산 = **RNG에서 오는 분산**
- 같은 시드·다른 전략의 결과 분산 = **선택에서 오는 분산**
- §32의 “결과 분산 대부분은 선택에서 와야 한다”를 이 두 값의 비율로 검증한다.

## 밸런스 목표 (초기값. 프리셋별로 시뮬레이션 후 재보정)

기본 프리셋(병립형 46)에서는 비례 5%가 약 2석, 8%가 약 3~4석이다. 원본의 구간(0~2/3~7/8~15/16+)은 이에 비해 후하므로 다음을 초기 가안으로 둔다.

```text
실패       0~1석   (0석이면 득표율에 따라 등록취소)
생존       2~6석
성공       7~12석
대성공     13석+
```

- 구간은 확률을 강제하기 위한 값이 아니라 **캘리브레이션 목표**다. 강제 확률로 만들지 않는다.
- 역사적 앵커(공개 결과이나 수치는 구현 전에 확인): 2016 국민의당, 2020 정의당, 2024 조국혁신당·개혁신당의 제3당 결과. 제3당이 실제로 얻은 의석 범위가 시뮬레이션 분포의 상·하한 감각을 준다.
- 정책을 엉성하게 만들고 지역조직을 무시하고 후보를 잘못 공천하면 0석도 가능해야 한다. 그러나 랜덤 운빨 게임도 아니다.
- RNG 사용처: 여론조사 오차, 캠페인 변동, 외부 충격 정도.
- AI 정당도 같은 정보·정책 엔진·유권자 모델을 쓴다. 치팅 금지.

# 31. 정치적 중립성, 실존 인물, 법적 주의

## 표시
- 실존 정당·정치인: `REAL-WORLD BASELINE` 배지
- 2026-10-19 이후 시뮬레이션: `SAVE SIMULATION` 배지
- 여론조사, 개표, Election Night에는 **“가상 시뮬레이션” 표시를 상시 노출**한다.

## 금지
- 정책 점수 92 = 좋은 정책, 정당 도덕성, 정치인 인격 점수 표시
- 실존 정치인에 대한 허구의 범죄·비리·건강·사생활 이야기 생성
- 실존 조사기관·방송사 이름과 디자인 사용

## 대신 표시
비용 / 수혜집단 / 부담집단 / 실행 난이도 / 효과 시차 / 정당 강령 일치

## 릴리스 체크리스트 (공개 배포 전)
1. `UNVERIFIED_ASSUMPTION` 항목을 모두 검증 또는 제거했는가
2. 실존 인물의 실제 지역구 낙선·당선 등 결과 표현이 “가상 시뮬레이션”으로 명확한가
3. 선거 6개월 전후 공개 배포 시 선거법상 문제 소지(여론조사 공표, 허위사실 등)에 대해 **전문가 검토**를 받았는가 (이 문서는 법률 자문이 아니다)
4. 데이터 출처와 이용 조건(공공데이터 이용 조건 등)을 확인했는가

# 33. Reality Pack과 데이터 단계

## Reality Pack 요구사항
- 모든 지표는 **기준일(asOf)**을 가진다. 모든 `REAL_FACT`는 출처와 검증일이 있다.
- 검증하지 못한 가정값은 `UNVERIFIED_ASSUMPTION`으로 따로 표시한다 (§7.4).
- 2026년 6월 지방선거 결과(지방의원 수 등), 2025년 대선과 2024년 총선 결과를 직전 선거 기준 데이터로 포함한다.
- 연령별 유권자 수, 시도별 인구 등은 공공통계에서 가져오고 출구조사 교차표는 집계 수준의 근사로만 쓴다.
- 현재 국정 평가 지표를 기준일과 출처와 함께 포함한다.
- 세이브 상태 필드는 Reality Pack에 들어가지 않는다.

## Validator (CI 실패 조건)
- 300 법정 의석, 현직 의석 + 공석 = 300
- 정당 ID 유효, 정치인 ID 중복 없음
- `REAL_FACT`에 출처·검증일 있음
- 지표에 날짜 있음
- 세이브 상태 누출 없음
- 가상 인물 이름이 실존 정치인과 충돌하지 않음
- 시도–권역 매핑 17개가 빠짐없이 한 권역에 할당됨
- 릴리스 빌드: `UNVERIFIED_ASSUMPTION` 없음

## 데이터 단계 (Data Tier)
처음부터 Reality Pack을 전부 채우지 않는다. (원본의 “Phase 1/2”는 개발 Phase A~E와 헷갈려 **Data Tier**로 개명했다.)

**Tier 1 (UI·루프 검증용)**
- 실제 정당 5개, 핵심 실존 정치인 10명, 가상 정치인 20명
- 6개 이슈, 96개 코호트
- Active 지역구 12개, 나머지 242개는 합성 Light baseline

**Tier 2**
- 실제 정당 전부
- Active 30개, 254개 Light 레코드를 2024 실제 결과로 채움
- 실존 Core Actor 20명, 가상 정치인 30명 + 월별 생성
