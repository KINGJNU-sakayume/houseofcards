# 로드맵 — C2 이후 (rev 2026-10-25)

C1 이후 남은 작업의 **순서와 분할**은 이 문서가 정합니다. 각 단계의 **세부 사양**은 계속 Slice Spec과 단계별 지시서에 있습니다. C2는 `docs/HOUSE_OF_CARDS_KOREA_phase_c_rev1.md` §13–22를 따르고, D와 E는 착수 전에 지시서를 작성합니다. 우선순위는 `DECISIONS.md`(사용자 결정) → Slice Spec → 이 문서 → 단계 지시서 → `AGENTS.md` 순입니다.

진행 상황은 `docs/PROGRESS.md`에 기록합니다. 실행할 때마다 그 파일의 **첫 번째 미완료 단계 하나만** 수행합니다.

## 1. 실행 규칙

남은 작업은 "토큰이 생길 때 한 번 달리는" 방식으로 진행합니다. 그래서 한 번의 실행이 한 단계를 끝내고, 녹색 상태를 남기고, 다음 실행이 이어받을 수 있어야 합니다.

1. **사전 점검.** 처음에 `npm ci --no-audit --no-fund`를 한 번만 실행합니다. 실패하면 `PROGRESS.md` 로그에 한 줄을 남기고 **즉시 종료**합니다. 재시도를 예약하거나 다른 경로로 우회하지 않습니다.
   - 2026-10-20~23에 클라우드 세션의 npm 레지스트리 차단으로 11번 연속 실패한 적이 있습니다. 해결 방법은 환경 네트워크 허용 목록에 `registry.npmjs.org`를 추가하거나, 사용자 컴퓨터에서 로컬로 실행하는 것입니다.
   - 예외적으로 `npm` 없이 할 수 있는 단계도 있습니다(표의 "npm" 열이 `불필요`인 단계). 이 단계는 Python 표준 라이브러리 스크립트와 문서만 다룹니다.
2. **브랜치.**
   - **개정 2026-10-25 (사용자 결정):** 단계마다 PR을 만들고, CI가 통과하고 문제가 없으면 바로 main에 병합합니다. 브랜치는 단계별로 `phase/c2`(C2a), `phase/c2b`, `phase/c2c`, `phase/d1` … 처럼 둡니다.
   - 따라서 단계마다 main에 배포됩니다. 상태 구조를 바꾸는 단계는 `schemaVersion`을 하나씩 올리고, 이전 스키마 JSON은 한국어 보관 안내와 함께 거부합니다(제자리 수정 금지).
   - 골든을 바꾼 단계는 그 PR에서 old→new 해시를 `DECISIONS.md`와 `PROGRESS.md`에 남깁니다.
3. **게이트.** 단계 완료로 표시하려면 `typecheck`, `lint`, `test`, `validate:data`, `sim -- --seeds 20`이 모두 통과해야 합니다.
   - 세션에 Chromium이 없으면 Playwright는 PR의 GitHub Actions 결과로 확인합니다.
   - 골든을 바꿨으면 바뀐 해시를 `PROGRESS.md`에 적습니다. 정식 old→new 기록은 단계군을 병합할 때 `DECISIONS.md`에 남깁니다.
4. **끝내지 못했을 때.** 진행분을 `wip:` 커밋으로 단계군 브랜치에 푸시하고, `PROGRESS.md`에 인계 메모를 남깁니다. 인계 메모에는 한 일, 막힌 점, 다음에 할 첫 명령을 적습니다. 완료 체크는 하지 않습니다.
5. **범위.** 한 실행에서 다음 단계를 시작하지 않습니다. 사양에 없는 결정을 했으면 `DECISIONS.md`에 기록합니다.

## 3. Phase D 데이터 준비

### 3.1 법적 수치 (DD1)

다음 항목은 법령 원문으로 확인합니다. 확인하지 못한 값은 `UNVERIFIED_ASSUMPTION`으로 두며, 이 값이 남아 있는 동안 릴리스 빌드는 실패합니다.

- **정당 등록취소.** 정당법 제44조 제1항 제3호(의석 0석이면서 득표 2% 미만이면 등록취소)는 **2014-01-28 헌법재판소 위헌 결정**이 있었습니다. 이 결정 이후 대체 입법이 있었는지를 법제처 현행 조문으로 확인합니다. 결과에 따라 §5의 결정 1을 정합니다.
- **기탁금과 반환 기준.** 지역구 후보와 비례 후보 각각.
- **선거비용 보전 기준.**
- **중복입후보 금지 여부.** 지역구와 비례대표 동시 입후보.
- **비례대표 성별 규칙.** 여성 비율과 순번 규칙.
- **2028 선거구 획정 상태.** 아직 미확정이라는 사실을 `UNRESOLVED`로 기록합니다.

### 3.2 원자료 (DD2, 사용자 제공)

인구 CSV 때와 같은 방식으로, 사용자가 받은 원본을 커밋하고 원본 인코딩·파일명·SHA-256을 기록합니다. 직접 재다운로드했다고 주장하지 않습니다.

1. **제22대 국회의원선거(2024-04-10) 지역구 개표결과 254개.** 선거구별 후보 정당, 득표, 선거인수, 투표수가 필요합니다. 출처는 중앙선관위 선거통계시스템입니다.
2. **같은 선거의 비례대표 정당별 득표.** 선거구 또는 그보다 작은 단위로 집계할 수 있는 것이 필요합니다.
3. **2024년 기준 선거구 구역표.** 공직선거법 별표 1(국회의원지역선거구구역표, 지역구 254)입니다. (DD1에서 정정: 별표 2는 시·도의회의원 선거구표) 선거구를 시군구·읍면동 단위로 연결하는 데 씁니다.
4. **읍면동별 연령 인구.** 행안부 자료이며, 기존 인구와 같은 기준월(2026-09)이면 좋습니다.

### 3.3 파생 규칙 (DD3)

- **지역구 목록.** 254개는 **2024년 기준 실제 지역구**입니다. 2028년 선거구는 미확정이므로 UI에 "이 세이브의 지역구는 2024년 기준입니다"를 항상 표시합니다.
- **연령 구성.** 4구간은 선거구 구역표 × 읍면동 인구에서 계산합니다.
- **프로필 구성.** 지역구별 근거 자료가 없으므로 권역×연령 조건부 질량(`profileConditionals`)을 그대로 씁니다. 이 한계를 문서에 적습니다.
- **정당 매핑.** 2024년 정당을 게임 정당(AI 5개 + 기타)으로 연결하는 매핑표를 데이터로 둡니다. 위성정당과 합당 관계는 출처와 함께 기록합니다.
- **Active 30 선정.** 권역별 쿼터는 서울 6, 경기·인천 8, 충청 4, PK 4, TK 2, 호남 2, 강원 2, 제주 2입니다. 2024년 1·2위 격차 같은 기준으로 결정론적으로 고르는 스크립트를 쓰고, 선정 기준을 pack에 기록합니다. 제주는 지역구가 3개뿐이므로 쿼터 2가 가능한지 검산합니다.
- **후보 이름.** 실존 후보나 현역 이름은 저장하지 않습니다(§5의 결정 2).

## 4. 모형 교정 (CAL)

현재 seed42 초기 관측 20개 중 15개가 ±5%p 범위 밖에 있습니다. 의석 배분을 붙이면 이 오차가 의석으로 증폭되므로 D2 전에 교정합니다.

- **타깃은 고정합니다.** 교정 대상은 `political-model.json`과 `b1.json` seed의 계수뿐이며, 타깃과 허용오차는 바꾸지 않습니다. 타깃과 허용오차를 바꿔 통과시키는 것은 여전히 금지입니다.
- **방법.** 결정론적 오프라인 탐색 스크립트(`scripts/calibrate.ts`)를 씁니다. 조정 가능한 계수 목록과 각 계수의 범위를 먼저 커밋한 뒤 탐색을 실행합니다.
- **검증.** 2026 지방선거 기반 20개 타깃에 맞추고, DD3의 2024년 권역별 결과를 **보류 검증용**으로 따로 보고합니다.
- **보고.** 교정 전후의 표와 남은 오차를 그대로 `VALIDATION.md`에 적습니다. 목표에 도달하지 못해도 정직하게 보고하고 진행합니다.
- **산출.** 정치 모형 버전 B3, 골든 재생성, `DECISIONS.md`의 old→new 기록.

## 5. 열린 결정 (사용자)

1. **0석 분기.** 등록취소 조항의 위헌 결정을 반영하는 것을 기본안으로 합니다.
   - 실제 법 기반 프리셋에서 0석은 득표율과 관계없이 원외 정당으로 존속합니다.
   - 등록취소는 Ruleset의 선택 파라미터로 남기고, "가상 입법 시나리오"로 표시합니다.
   - DD1 결과(2026-10-25): 정당법 2026-07-29 시행본에도 §44①3은 단순위헌 주석만 있고 대체 조항이 없다. 기본안을 뒷받침하며, D4 전에 사용자가 확정합니다.
2. **AI 정당 지역구 후보.** 실제 지역구를 쓰더라도 후보는 생성한 가상 Light 레코드로 두는 것을 기본안으로 합니다. 실존 정치인은 검증된 Tier 2 자료가 없어 유예한 상태이기 때문입니다. 실명을 쓰려면 별도 결정과 출처가 필요합니다.
3. **DD2 원자료 제공.** 사용자가 §3.2의 파일을 받아 첨부합니다.
4. **정리.** `claude/c2` 브랜치에는 진행 로그만 있습니다. 삭제할지, `phase/c2`로 대체할지 정합니다. 꺼져 있는 예약 작업 "houseofcards C2 자동 개발"을 다시 쓸지도 정합니다.
