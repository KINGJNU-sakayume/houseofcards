# Decisions — Phase A (역사적 기록의 시작)

## 2026-10-18 · 실행 범위와 문서 권한

사용자는 `KINGJNU-sakayume/houseofcards` 저장소에서 첨부 문서를 기준으로 구현하라고 확인했다. 첨부 프롬프트의 `CURRENT PHASE: A`와 한 작업당 한 단계 규칙을 적용한다. 원본 첨부 문서 3개는 저장소에 보존했다. 다음 단계 구현을 시작하지 않는다.

## Foundation 프리뷰의 정직한 경계

주간 달력, 기록 확인, 세이브, 기술 기반만 동작한다. 후속 메뉴는 탐색 가능하지만 미구현 표시 외에 가짜 수치·버튼·차트를 제공하지 않는다. 매주 3~7개 실제 정치 업무 보고는 후속 시스템이 있어야 의미가 있으므로 지금은 주간 일정 안내 하나만 생성한다. 수신함은 최근 12개를 보관하고 전체 이벤트/명령 기록은 남긴다. 안내를 보냈다는 이유로 실제 정치 통계를 계산했다고 표현하지 않는다.

## 데이터와 법적 가정

현재 번들에는 정치인·정당·국회 의석·현실 지표·법률의 실제 사실 레코드가 없다. `FOUNDATION_ONLY` pack은 비어 있는 정치 데이터와 17→8 게임 권역 매핑을 명시한다. 이는 Data Tier 1을 완성했다는 의미가 아니다. 원본 문서의 2026년 법제·정당 동향 주장은 이번 단계에서 독립 검증하지 않았으며 실제 데이터로 복사하지 않는다.

검증기는 §33의 300석/공석 합계, ID/참조, 출처/검증일, 지표 기준일, 날짜 형식, 세이브 누출, 이름 충돌, 시도 매핑, 릴리스 가정값 차단을 구현한다. `FOUNDATION_ONLY`에 정치적 레코드가 들어오면 실패한다. BASELINE은 국회·정당·집권당을 요구한다. 릴리스 모드에서도 빈 foundation pack의 불완전성 경고는 유지하지만 배포를 막지는 않는다. `UNVERIFIED_ASSUMPTION`은 어느 모드의 pack에서도 릴리스 오류다. 테스트의 synthetic baseline/인물은 테스트 전용이며 번들에 포함하지 않는다.

## Ruleset와 세이브 확장

선거 프리셋 구현은 Phase D이다. Phase A는 `foundation_calendar_only`라는 명시적, 선거 계산이 불가능한 스냅샷을 저장한다. 달력만 포함하며 의석·문턱·기탁금·등록취소 값은 제공하지 않는다. 이 스냅샷을 실제 선거제도라고 표시하지 않는다. 향후 ElectionRuleset 인터페이스에는 3개 프리셋을 표현할 모든 필드와 준연동형 옵션을 마련했다. 엔진 배분 훅은 Phase D에 구현한다.

아직 존재하지 않는 정당/자원/AI/코호트/후보 등의 저장 필드는 빈 숫자로 채우지 않고 해당 단계에서 스키마를 올려 추가한다. 현재 세이브는 정확히 Phase A 스키마 1을 받아들인다. 알려지지 않은 버전은 오류로 보존하며 묵시적으로 업그레이드하지 않는다.

## 달력 산술과 사양의 77틱 불일치

독립 날짜 계산 및 경계 테스트에서 사양의 숫자 불일치를 확인했다. 2026-10-19와 2028-04-10 사이에는 539일 = 77주가 있으므로 양 끝을 포함하면 월요일 78개, 날짜 전진은 77회다. 사양의 명시적 시작일·종료일·7일 간격을 우선하고 “77틱”은 77번의 ADVANCE_WEEK로 해석한다. 새 프리뷰는 1주차이며 마지막은 78주차다. 원본 사양은 수정하지 않는다. 날짜 계산은 ISO 날짜와 명시적 UTC 자정만 사용하고 현재 시각/로컬 시간대에 의존하지 않는다. 월말 틱은 다음 월요일이 다른 달인 월요일이다. 선거일은 사양의 게임 일정이며 법률 확인을 의미하지 않는다. Phase A는 마지막 월요일에서 멈춘다.

## 결정론

RNG는 `(uint32 seed, subsystem, ISO date)`의 JSON 튜플에서 FNV-1a 32 seed를 파생하고 xorshift32와 rejection sampling으로 정수를 만든다. 스트림 위치는 세이브에 기록된다. 현재 RNG의 유일한 사용처는 가상 일정 담당 직책 선택이며 지지율/정치 결과는 없다.

상태 해시는 정렬한 키/원래 배열 순서를 가진 canonical JSON에 FNV-1a 64를 적용한다 (UTF-16 코드 유닛). 로케일 정렬, 시간, random, exp/log/pow는 결과 경로에 없다. 해시는 재생·손상 확인용이며 보안 서명이 아니다. 고정소수점 유틸은 Q6, half-away-from-zero, safe integer 범위를 사용한다. exp는 범위 ±8, /16 축소와 12항 테일러 후 4회 제곱이며 Phase B 효용 모델 도입 때 정밀도를 재검토한다.

## UI와 저장

UI는 명령만 dispatch한다. Worker는 상태와 명령을 받아 같은 순수 엔진을 호출한다. Worker 미지원/초기화 오류/8초 무응답에는 동일 명령을 메인 스레드에서 실행한다. UI에서는 실행 방식과 해시를 세이브의 접힌 진단 영역에만 표시한다.

IndexedDB 자동저장은 모든 성공한 상태 변경 후 수행한다. 수동 슬롯은 별도다. 쓰기 transaction 완료 전 성공으로 표시하지 않는다. 저장 실패 시 플레이 상태는 보존하고 JSON 내보내기 안내를 제공한다. JSON 가져오기는 파싱·스키마·해시·명령 재생을 모두 통과한 뒤에만 교체한다. 새 프리뷰/불러오기/가져오기는 교체 안내를 먼저 띄운다. 다중 탭 동시 편집은 현재 last-writer-wins이며 합치기/탭 잠금은 미구현이다.

## 배포와 CI

Vite base `/houseofcards/` + HashRouter를 선택했다. 서비스 워커 없이 로드 후 오프라인 진행을 지원한다. 전체 오프라인 재접속은 별도 범위다. `main` CI가 전부 통과하면 공개 Phase A 프리뷰를 Pages로 배포한다. 미검증 법률값이 없는 foundation-only 빌드이며 정치 데이터가 들어가는 후속 릴리스는 원본 릴리스 체크리스트를 다시 충족해야 한다.

PR/매일 검사에서 각각 20/500 시드 달력 재생을 수행한다. 이를 AI-only 선거 시뮬레이션이나 밸런스 검증이라고 부르지 않는다. Phase B 이후 실제 AI와 선거 엔진에 맞춰 확장한다.

# Phase B1 · 2026-10-18

## 작업 범위와 기존 기반

첨부 rev2의 `CURRENT STEP: B1`만 실행한다. 원본 작업 지시를 `HOUSE_OF_CARDS_KOREA_phase_b_rev2.md`에 보존했다. 이전 프롬프트의 CURRENT PHASE A는 역사적 원문이며 이번 작업 지시를 대체하지 않는다. 순수 엔진·불변 상태·명령·Worker·폴백·IndexedDB·HashRouter와 시각 디자인은 유지했다. 월간 보고와 단계 안내만 갱신했다. 투표 모델, AI 행동, 정부 AI, polling, 자원, 창당 및 후속 UI를 구현하지 않는다.

## 스냅샷과 스키마

기존 foundation pack의 2026-10-19 표기는 시뮬레이션 시작과 현실 기준일을 혼동했다. `kr-b1-2026-10-18` / `realityPackAsOf=2026-10-18`, `simulationStartDate=2026-10-19`로 분리했다. 시작일·77번 전진·선거 시나리오 날짜는 바꾸지 않았다. 원본 Slice Spec의 시작일과 충돌하지 않는다. 예전 구현 프롬프트의 현실 스냅샷 10월 19일 문구는 이번 명시적 경계로 정정한다.

스키마는 2, 단계 구분은 B1이다. 외부 JSON envelope version 1은 전송 형식이며 상태 스키마 버전과 다르다. 스키마 1은 명시적인 한국어 오류로 거부한다. 기존 JSON을 보관하도록 안내하고 상태를 생성해서 마이그레이션하지 않는다. 실제 Phase A 원본으로 만든 fixture를 검증한다. 명령 한도는 기존 codec의 1,000개를 엔진에서도 지키며 이벤트 한도는 월간 경계 기록까지 수용한다.

## 32개 레버와 공약/집행

Slice §11의 6/5/5/5/6/5개 레버를 그대로 유지했다. 0~4, 현행=2, 한국어 명칭/축, 열 핵심가치 태그, 상대 재정부담, 효과 채널, 불확실성, 월 단위 시차를 데이터로 둔다. 모든 계수는 게임 모형이며 현실 예산·인과 효과를 주장하지 않는다. 재정부담 메타데이터는 준비했지만 B2 재원 신뢰/투표 판단은 아직 없다.

모든 정당은 같은 Platform 구조를 쓴다. 실제 네 정당의 주제 태그를 Seeds에서 해석해 넓은 prior와 독립 `platform-priors` RNG로 초기 공표값을 만든다. 기타 세력 묶음은 실존 정당이 아닌 Seed 객체다. 플레이어 개발 객체는 미공표다. 편집 가능한 값 2는 초안일 뿐 현행 정책 지지를 공표한 것이 아니다.

`SET_PLATFORM_DRAFT`는 초안/명령 기록만 바꾸고 `simulationFields` 해시 및 미래 이슈를 바꾸지 않는다. `PUBLISH_PLATFORM`은 플레이어 개발 객체에만 작용한다. 비용은 Phase C로 유예한다. 현행 2의 양쪽을 넘는 반전은 최근 **6 달력 월** 내 마지막 방향성 공표를 참조해 2,500/10,000의 일관성 부담을 누적한다. 중간에 2를 공표해도 기억이 사라지지 않는다. 월별 400씩 감소한다. 신뢰에 연결하는 것은 B2다.

정부 집행은 별도 객체이며 모든 초기값은 2다. `enactPolicy`는 집권당 actor만 허용하는 엔진 전이로, 플레이어 명령이 없다. 이력에서 시차가 만료된 마지막 값을 읽는다. 새 집행이 이전의 이미 발효된 효과를 소급 취소하지 않는다. 정치개혁 레버도 Ruleset을 바꾸지 않는다.

## 사회 이슈의 작은 월간 모형

정수 0~10,000 = 화면 지수 0~100이며 `trend`는 직전 월 대비 정수 차이다. `structuralPressure` 범위는 −1,000~1,000이다. 지수는 통계가 아닌 Seeds다.

각 adverse-condition driver는 `초기 driver + structuralPressure × 10 + 발효 정책 채널의 합`이라는 목표로 관성 이동한다. 가중 driver 평균에 이전 월의 교차 영역 압력을 더해 severity 목표를 만들고 다시 관성 이동한다. salience 목표는 severity 60% + 초기 관심 40%, 변화량과 충격의 절댓값을 반영하고 별도 관성을 가진다. 값은 정해진 반올림 후 범위 제한한다. 모든 영역은 같은 이전 월 스냅샷을 읽으며 순서에 의존하지 않는다.

주택은 공급/금융/임차, 가족은 주거/돌봄/일가정, 연금은 기여 부담/노후 불안/재정(고령화는 구조압력), 의료는 지역 접근/인력/비용, 산업·AI는 투자/R&D/인프라/에너지/세계 수요, 정치개혁은 제도 신뢰/대표성 driver다. 산업 수요를 포함한 외생 충격은 `issue-shocks` 스트림의 월별 영역 충격이며 실제 뉴스 재현이 아니다. 공급·가족 효과는 24~36개월, 의료인력은 60개월 등 긴 시차가 시즌을 넘어갈 수 있다. B1에는 정부 AI가 없으므로 기본 플레이에서 집행값은 2로 유지되고 구조압력·충격만 진행한다. 집행 효과는 엔진 전이 테스트로 검증한다.

## 코호트와 결정론

권역×연령 주변질량을 Reality에서 받아 Q6(총 1,000,000)로 정규화한 뒤, 각 셀의 정수 질량을 Seeds의 세 생활조건으로 분배한다. 각 단계에서 최대잔여·ID 동률처리를 사용해 합을 정확히 보존한다. 큰 수의 곱/나눗셈은 BigInt로 처리한다. 작은/0 질량도 셀을 없애지 않는다. Seed 조건부 분포는 비균등하며 고령의 Asset & Retirement와 수도권 청년의 Housing Pressure 비중이 높다.

선호/관심/참여 성향은 생활조건 Seeds에서 오며 정당 ID로 만들지 않는다. 정당 attachment는 별도 `cohort-calibration` RNG와 Seed 정당별 질량으로 초기화한다. 이 값은 **현실 득표와 아직 교정하지 않은 개발 모형**이며 B2 전 유권자 지지로 보여주면 안 된다. `calendar-reports` 수열은 변경하지 않았다. 모든 outcome 연산은 정수/고정 반올림이며 wall clock/random/exp/log/pow를 새로 도입하지 않았다.

## 사용자 확정: 전체 정당의 장벽을 제거하는 Potential

Slice Spec과 B2 rev2 §14의 대상 범위가 달라 사용자에게 확인했다. 답변은 **“Slice Spec의 전체 정당 장벽 제거 적용”**이다. Potential은 모든 정당의 A=1, 모든 정당의 V=동일한 중립값으로 계산한다. 중립값은 현재 전국 지지 상위 두 정당 V의 중앙값(두 값의 평균)이다. 신뢰·기존 충성·정체성·정부평가는 유지한다. 정당 하나만 바꾸는 B2 rev2 정의를 적용하지 않는다. Potential≥Current를 강제로 보정하지 않는다.

장벽 분석의 인지도·생존가능성·적합·신뢰는 각각 현재 조건에서 한 가정만 바꾸는 독립 반사실이다. 기존 충성은 전체 Potential 조건에서 모든 충성을 추가로 중립화한 차이다. 상호작용과 기준 차이가 있으므로 합산하지 않는다. UI에 기준과 비가산성을 명시했다. 내부 분석의 ±1.5%p 표시 폭은 구성 가능한 모형 설명 범위이며 통계적 신뢰구간이 아니다.

## 유권자 모형과 관성

`political-model.json`에 B2.1 게임 계수를 모았다. 인지도는 공표 범위·관심·정치 관심·신선도에 따른 월간 노출로 천천히 증가하고 소폭 감소한다(growth .085, decay .0035, cap .98). 소유 인식은 .10, 정체성은 .12의 관성으로 이동한다. 기존 충성은 초기 prior이며 불만족 시 .007의 작은 비율로 침식될 뿐 지지율로 자동 강화하지 않는다. 초안은 모든 유권자 입력에서 제외한다. 공표 자체는 지지를 직접 변경하지 않고 다음 월간 계산에 들어간다.

## AI와 월간 순서

월간 순서는 일관성 부담 감소 → 정당 AI → 정부 AI → 시차가 만료된 집행에 따른 이슈 → 인식/lagged V → 지지 분석 → 새 조사다. 각 정당 AI는 ID순, 독립 named stream으로 행동한다. 최근 공개 조사의 전국·연령·권역 범위와 공유 생활조건 prior, 사회 이슈, 원래 공약 prior, 일관성·재정부담을 읽는다. 숨겨진 Current·인지도·충성을 읽지 않는 별도 테스트가 있다.

정당 AI는 월 1개/분기 2개 이하 레버를 한 단계씩 바꾼다. 원래 공약에서 멀어지는 비용(.65)과 비플레이어 정당 간 평균 쌍별 레버거리 하한 .10으로 동일화에 제동을 건다. 정부 AI는 분기 말 월간 틱에 분기 최대 1개를 자기 공약과 이슈·재정부담에 따라 집행한다. 야당 공표를 정부 집행으로 복사하지 않으며 기존 `enactPolicy`와 효과 시차를 사용한다.

## 가상 조사와 오차

나루 의견연구소·모래숲 조사실·새결 공론연구소는 모두 가상이다. `poll-house-effects`에서 기관×정당 편향을 한 번 생성해 저장하고 계속 재사용한다. `poll-sampling`은 12개 균등 난수 합의 결정론적 정규근사로 표본 잡음을 만든다. 전국 n=1,200, 설계효과 1.15, 기관 편향 원래 draw 범위 ±.002다. 점 추정치는 none을 포함해 정규화한다. 전국과 부분 표본은 서로 별도로 생성하는 경량 모형이므로 하위 조사 합으로 전국 조사를 재구성하지 않는다.

오차는 p(1−p)·deff/n에서 정수 제곱근으로 도출한다. 0/100%에는 반 관측값 조정을 하고 기관 불확실성을 합성한 뒤 1.96을 적용한다. 연령/권역 n은 투표성향 가중 질량에서 산출하므로 작은 부분 표본의 범위가 더 넓다. 내부 Potential은 여론조사 입력이 아니다. 300개 시드의 테스트 전용 6%/35% 진실값으로 전국 구간 coverage를 검사하며 허용 범위는 .88~.995다. 이는 근사 모형의 smoke 검사이지 모든 정당·하위집단에서 명목 95%를 보증한다는 뜻이 아니다.

# C2a — 가상 정치인 생성기 (2026-10-25, `phase/c2`)

ROADMAP의 C2a 단계(phase_c §13)만 실행했다. 영입·약속(C2b), 지역조직·노출 채널(C2c), 브랜드 일관성(E2)은 구현하지 않았다.

- **스키마.** `schemaVersion: 4`, `phase: 'C2'`, 상태에 `politicians`(id 순, 최대 80) 추가. 실제 C1 엔진으로 내보낸 `tests/fixtures/phase-c1-v3.json`은 한국어 보관 안내와 함께 거부한다. A/B1/B2 거부도 유지한다. 단계마다 main에 병합하므로(아래 진행 방식 개정) C2b/C2c는 스키마를 제자리에서 바꾸지 않고 5, 6으로 올린다.
- **데이터.** `src/data/seeds/politicians.json`(C2.0, GAME_MODEL, strict zod): 성 30개 × 이름 60개, 배경 14종(가중치·속성/영역 편향·연관 가치), 생성 파라미터. 수치는 게임 밸런스 값이며 현실 통계가 아니다.
- **속성.** Slice §20.4의 7개 속성 + 영역별 PolicyExpertise만 둔다(0–100 정수). `valueLean`은 2개 가치에 Q6, `domainInterest`는 0–100. 도덕성·정직·건강 등은 없다. 사양 필드 외에 생성일 `generatedAt`만 추가했다(만료·표시용).
- **생성 규칙.** stream `(seed, 'politician-pool', date)`만 쓴다. 창당 시 30명, 이후 월간 틱마다 1–3명을 뽑는다. 2027-12-06까지 누적 50명을 보장하기 위해 각 월간 틱에서 `ceil((50 − 누적) / 남은 월간 틱 수)`보다 적으면 그만큼 채운다. 전체 생성 수는 80명을 넘지 않는다. 권역은 코호트 인구 가중치 × `regionWeight` 훅(C2c 후보발굴용, 기본 1)이고 훅은 확률만 바꾸며 인원은 바꾸지 않는다. 선언가치는 배경·성향 추첨 가중치에만 반영한다(능력치 보너스 없음). 이 가중치는 초기 풀뿐 아니라 월간 공급에도 같은 방식으로 적용했다(사양에 없는 결정).
- **만료.** 영입되지 않은 후보는 생성 후 30주가 지나면 `unavailable`이 된다. 생성 상한이 80명이므로 저장 크기는 제한된다. C2b 전까지는 영입이 없으므로 시즌 말에는 대부분 만료된다.
